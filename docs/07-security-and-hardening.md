# 第 7 步：安全加固（面板 / SSH / 凭据）

前六步解决的是"能不能用"，这一步解决"用起来安不安全"。路由器上跑的是一台**局域网网关**，一旦被别人拿到面板或 SSH，等于把你家网络的全部流量和配置交出去。

---

## 7.1 给面板加密码、换端口

面板默认监听 `9999`，而且**默认没有密码**。任何能连到你局域网的人（访客 WiFi、租客、被入侵的 IoT 设备）都能直接打开它，看你的节点、改你的规则、把流量切到他自己的服务器上。

```text
主菜单 2 功能设置
   → 修改面板访问端口        # 比如改成 19099
   → 设置面板访问密码        # 设置一个强密码
```

改完重启服务，用新地址访问：

```sh
/data/ShellCrash/start.sh restart
```

```text
http://192.168.31.1:19099/ui/
```

验证密码是否生效（未带密码应当被拒绝）：

```sh
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.31.1:19099/version
# 期望：401（说明 secret 生效）
```

> ShellCrash 的"功能设置"里还有 **TUN 模式、局域网访问控制** 等开关。用不到的（比如 TUN）关掉，既省内存（见第 6 步的 OOM 章节）也少一层攻击面。

---

## 7.2 不要把管理端口暴露到公网

这三样东西**绝对不要**做端口映射 / 端口转发：

| 端口 | 服务 | 暴露后果 |
| --- | --- | --- |
| `22` | SSH (dropbear) | 会被全网扫端口爆破，弱密码几分钟就被打穿 |
| `9999` | 面板 / API | 面板可直接改配置、看节点、导流量 |
| `7890/7891/7892/7893` | 代理端口 | 别人可以白嫖你的节点，流量算在你头上 |

同时检查小米后台：

- 后台里的"**外网访问** / 远程管理 / DDNS 映射"保持**关闭**
- 别在光猫或上级路由器上把上述端口转发到这台机器

如果确实需要在外面访问面板，用下面任一方式，**不要裸奔**：

1. **VPN / 内网穿透**：Tailscale、WireGuard 接进家里网络后再访问 `http://192.168.31.1:9999`（ShellCrash 的"访问与控制"里有 Tailscale 集成，限 Sing-box 内核）
2. **反向代理 + HTTPS + 强密码**：仅在你明确知道自己在做什么时使用

---

## 7.3 SSH 加固

解锁脚本给你的是"能登录"，不是"安全登录"。至少做这两件事：

```sh
# 1) 确认 root 密码不是弱口令（xmir-patcher 主菜单 8 → 2 可改）
#    不要用 123456 / admin / 路由器后台密码
```

**不要在路由器上开放公网 SSH**（见 7.2）。局域网内使用已经足够。

如果一定要在局域网外登录，改用密钥 + 非标准端口，并在上级设备上做来源 IP 限制：

```sh
mkdir -p /etc/dropbear
# 把你电脑的 id_ed25519.pub 内容追加进去
vi /etc/dropbear/authorized_keys
chmod 600 /etc/dropbear/authorized_keys
```

> 老固件的 dropbear 对密钥类型挑剔，优先用 `ssh-rsa` 或 `ssh-ed25519`，并在客户端加 `-o PubkeyAcceptedAlgorithms=+ssh-rsa`。

## 7.4 凭据保密：哪些东西不能外传

| 信息 | 泄露后果 |
| --- | --- |
| **订阅链接** | 等于把你的机场账号给别人用，流量和费用都算你的；部分机场会因此封号 |
| **节点 UUID / 密码 / REALITY 公钥+SNI** | 别人可以白嫖你的自建 VPS，甚至通过你的节点做违法事情，责任在你 |
| **路由器后台密码 / SSH 密码** | 别人可以直接改你家网络配置 |
| **面板地址 + 密码** | 同上 |

**实操建议**

1. 往公开仓库、论坛、群聊贴配置前，先把关键字段替换成占位符（`<你的UUID>`、`node.example.com`）
2. 截图时把订阅地址、节点地址、UUID 打码
3. 本教程仓库里的所有节点参数**都是占位符**，没有任何真实凭据
4. 如果不小心泄露了：机场订阅在后台**重置订阅链接**；自建节点**重新生成 UUID/密码**并重启服务端

快速自查（在你准备分享的目录里跑）：

```sh
# 找出疑似真实凭据的行
grep -rniE '([0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12})|(//[^/]*:[^@/]+@)|(https?://[^ ]*/sub[?/])' .
```

任何一条命中，都要先确认是不是占位符再决定是否公开。

## 7.5 备份文件也要当敏感文件对待

第 5 步（备份与恢复）产出的包里包含：

- `configs/ShellCrash.cfg`（含**订阅链接原文**和 UA）
- `yamls/*.yaml`（含**全部节点参数**）
- `ui/`、规则文件

所以备份包**不要**丢到公开网盘或 Git 仓库。建议：

```sh
# 备份时顺手加密（本机加密，不占路由器内存）
# 把包拉到电脑后再加密，别在路由器上压缩（见第 6 步 OOM）
gpg -c shellcrash-backup.tar.gz     # 会生成 .gpg，需要密码才能解开
```
